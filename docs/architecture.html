PyVista Demos · 科学可视化演示集

十二个跨学科的 3D 科学场景，通过 PyVista / VTK 离屏渲染，输出透明背景 PNG，作为科学可视化的参考图集与质量基线。

1产品概述

PyVista Demos 是一个演示性质的科学可视化项目。它不面向最终用户提供应用，而是以 catalog.json 描述的十二种场景为单位，程序化地生成高质量、透明背景的 3D 渲染图， 用于视觉回归测试、配色方案验证以及科学可视化组件的参考样例。

◆

十二种科学场景

覆盖地形、流体、波动物理、材料、有限元、分子、点云、测地线、张量、血管、地震、城市气流等领域。

●

离屏渲染管线

基于 PyVista + VTK 的 off-screen 渲染，无需 GUI 环境即可生成 1600x1000 高清透明 PNG。

★

确定性与可复现

所有场景使用固定相机位置、固定调色板、确定性场函数，输出可逐像素复现，适用于快照测试。

✓

内置图像质量校验

渲染后自动验证 Alpha 通道比例、可见像素占比、彩色像素数量，防止空图或渲染异常。

≡

结构化目录清单

catalog.json 记录每个场景的用途、科学问题、视觉家族、复杂度与标签，便于程序化检索。

⇄

单场景或全量渲染

CLI 支持 --scene 过滤单个场景，默认全量输出；结果以 JSON 报告形式返回。

2系统架构

项目采用「入口层 → 场景构建层 → 渲染引擎层 → 输出校验层」的四层线性结构。 每层职责单一，通过明确的数据对象（场景 ID、Plotter 实例、PNG 文件）串联。

分层职责说明

入口层 是 CLI 的唯一入口，由 main() 函数构成。它解析 --scene 与 --out 参数，确认目标场景集合，创建输出目录，然后逐个调用渲染函数，最后将校验结果汇总为 JSON 打印到标准输出。该层不包含任何绘图逻辑，只负责调度与报告。

场景构建层 是项目的核心内容，由 12 个独立的 builder 函数和一个 BUILDERS 字典构成。每个函数内部先用 NumPy 生成确定性的场数据（结构化网格、向量场、粒子集等）， 然后转换为 PyVista 的 mesh 对象（StructuredGrid、ImageData、PolyData 等），设置颜色映射、透明度、光照等渲染参数， 最后返回配置好的 Plotter 实例。所有场景共享统一的调色板 PALETTE 和相机位置风格。

渲染引擎层 封装了 PyVista / VTK 的离屏渲染流程。render() 函数从 BUILDERS 获取 Plotter，调用 show(auto_close=False) 触发渲染管线，再通过 screenshot(transparent_background=True) 捕获透明背景的帧缓冲，最后关闭 Plotter 释放资源。 该层是与第三方库耦合最深的一层，但被限制在单个函数内。

输出校验层 由 validate_png() 提供质量闸门。它用 Pillow 打开 PNG 并转为 RGBA，统计完全透明像素比例、可见像素比例和彩色像素数量（R/G/B 最大差 > 24 且 Alpha > 16 的像素数）， 三项任一低于阈值即抛出异常。这保证了渲染失败、空图、纯灰度图等异常情况能被自动检测。

关键数据对象

SCENES 元组 是场景 ID 的权威清单，定义于 __init__.py。 它既是 CLI 选项的 choices 来源，也是测试中校验 BUILDERS 字典完整性的基准。 catalog.json 则是对同一批场景的补充描述，提供人类可读的用途说明和标签。 两者通过 id 字段一一对应，但来源不同：SCENES 在代码中，catalog 在配置中。

Plotter 实例 是场景构建层与渲染引擎层之间的接口对象。每个 builder 返回一个已经配置好 mesh、相机、光照、文字的 Plotter，render() 只需调用 show + screenshot，不需要知道场景的具体内容。 这种分离使得新增场景只需写一个 builder 并注册到 BUILDERS，渲染逻辑完全复用。

校验结果字典 包含 scene、size、transparent_pct、visible_pct、colorful 五个字段， 既用于运行时异常检测（阈值不满足时 raise），也用于最终 JSON 报告。测试合约 test_rendered_gallery_contract 进一步确保 out/ 目录下每个场景都有对应 PNG 且质量达标。

4主走查 · 全量渲染

以「执行 uv run render-pyvista-demos 渲染全部 12 个场景」为端到端场景， 逐步追踪从命令启动到输出 PNG 报告的完整路径。

1

CLI 入口解析与初始化

argparse 解析 --scene 和 --out 参数；未指定 --scene 时使用 SCENES 全量列表。创建输出目录 out/（如不存在）。

2

按场景迭代 · 调用 render()

遍历选定的场景 ID 列表，对每个场景调用 render(scene, output_path)。单场景失败会中断整个流程（异常冒泡）。

3

场景构建 · 生成 Plotter

从 BUILDERS 字典查找对应 builder 函数，执行之。内部用 NumPy 生成场数据 → 组装 PyVista mesh → 添加到 Plotter → 设置相机。返回配置完成的 Plotter 实例。

4

离屏渲染 · 截图落盘

调用 plotter.show(auto_close=False) 触发 VTK 渲染管线，再以 screenshot(transparent_background=True) 捕获帧缓冲并写入 PNG 文件。

5

图像质量校验

Pillow 读取刚生成的 PNG，统计 Alpha 直方图与彩色像素数。透明像素 < 6%、可见像素 < 3.5% 或彩色像素 < 2500 任一不满足即抛 RuntimeError。

6

汇总报告 · JSON 输出

全部场景渲染校验完成后，将每个场景的校验结果字典收集为列表，以格式化 JSON 打印到标准输出。调用方可解析该报告做进一步自动化处理。

场景设计约束

每个场景都遵循相同的隐形约定：画布尺寸 1600×1000、深色背景 （用于透明渲染时的视觉参考，实际输出为透明）、左上角两排标题与副标题文字、固定调色板 PALETTE 的五种主色、统一的斜视等距相机视角。这些约束确保十二张图放在一起时 视觉风格一致，可作为统一的图集使用。

数据层面，所有场函数均为纯数学合成（无外部数据文件依赖），使用确定性随机种子（如 default_rng(42)），保证跨平台、跨版本的渲染结果可复现。 这一特性使项目天然适合作为可视化工具链的回归测试基准。

6测试与质量保障

项目采用轻量但闭环的测试策略：结构一致性测试 + 输出合约测试， 配合运行时图像校验，形成三层质量防线。

设计考量

三层防线的设计体现了「快失败优先」原则：第一层结构测试不依赖渲染，在 CI 中可以毫秒级反馈， 防止「新增了场景但忘了注册」这类低级错误混入。第二层运行时校验嵌入渲染流程本身， 确保任何一张异常输出都不会静默通过。第三层输出合约测试则是对 out/ 目录完整性的最终审计， 在发布前或 CI 的完整流程中运行。

项目未引入像素级快照对比（snapshot diff），因为不同 VTK 版本、不同驱动的 OpenGL 实现可能导致 亚像素级差异。选择基于统计量（像素计数、比例）的校验是在稳定性与严格性之间的有意权衡。
